## 1. Система типов данных в Java
Java является языком со строгой статической типизацией. Каждой переменной или выражению должен быть задан тип данных, который определяет:
- диапазон допустимых значений;
- объём занимаемой памяти;
- набор операций, применимых к данным.

Все типы данных в Java подразделяются на две категории: **примитивные** и **ссылочные (объектные)**.

---
## 2. Примитивные типы данных
Примитивы представляют собой базовые типы, предназначенные для хранения простых значений. Их ключевые характеристики:
- хранят строго одно значение;
- диапазон допустимых значений и объём памяти фиксируются на этапе компиляции;
- поддерживают прямые операции сравнения (`==`, `<`, `>`) и арифметические вычисления без вызова вспомогательных методов;
- не могут принимать значение `null`.

Примитивные типы классифицируются на четыре группы (восемь видов):
1. **Целочисленные:** `byte`, `short`, `int`, `long` — хранят положительные и отрицательные целые числа.
2. **С плавающей точкой:** `float`, `double` — хранят вещественные числа с дробной частью.
3. **Символьный:** `char` — хранит числовой код символа из таблицы Unicode (всегда неотрицательное значение).
4. **Логический:** `boolean` — принимает значения `true` или `false`.

**Оптимизация использования памяти:** Выбор типа данных напрямую влияет на производительность. Например, при работе с массивами, содержащими значения в диапазоне до 100, целесообразно использовать тип `byte` (1 байт) вместо `int` (4 байта), что позволяет сократить потребление памяти в четыре раза.

---
## 3. Ссылочные (объектные) типы данных
К данной категории относятся все типы, не являющиеся примитивами: классы, интерфейсы, массивы, строки (`String`) и классы-обёртки.

Особенности ссылочных типов:
- переменная хранит не само значение, а ссылку (адрес) на объект в памяти;
- размер объекта заранее неизвестен и может динамически изменяться в процессе выполнения программы;
- ссылка на объект на 64-битных системах занимает 64 бита;
- массив объектов хранит набор ссылок фиксированного размера, в то время как сами объекты располагаются в других участках памяти. Это обеспечивает экономию ресурсов и повышает скорость работы программы.

---
## 4. Модель памяти JVM: Стек и Куча
Виртуальная машина Java (JVM) разделяет оперативную память на две основные области для оптимизации выполнения приложений.

### 4.1. Стек (Stack)
Стек — это ограниченный по размеру участок памяти, предназначенный для хранения локальных переменных, параметров методов, примитивных значений и ссылок на объекты.
- **Принцип работы:** Управляется по принципу LIFO (Last In, First Out). При вызове метода создаётся новый фрейм (кадр стека), который размещается на вершине. По завершении работы метода фрейм автоматически удаляется.
- **Скорость:** Обеспечивает высокую скорость доступа за счёт строгой последовательности выделения и освобождения памяти.
- **Жизненный цикл данных:** Данные имеют временный характер и удаляются сразу после выхода из области видимости метода.
- **Ошибка переполнения:** `java.lang.StackOverflowError` (возникает при превышении лимита, например, из-за бесконечной рекурсии).

### 4.2. Куча (Heap)
Куча — это область памяти, используемая для долговременного хранения всех создаваемых объектов и массивов.
- **Принцип работы:** Доступ к данным возможен из любой части программы при наличии активной ссылки. Управление памятью осуществляется автоматически с помощью сборщика мусора (Garbage Collector), который выявляет и удаляет неиспользуемые объекты.
- **Структура:**
  1. `Young Generation` — область для новых объектов. При заполнении запускается сборка мусора.
  2. `Old (Tenured) Generation` — область для объектов, переживших несколько циклов сборки в Young Generation.
  3. `Metaspace` (начиная с Java 8) — хранит метаданные загруженных классов, статические поля и информацию о методах (заменяет `PermGen`).
- **Важное правило:** Если переменная примитивного типа объявлена как поле объекта, она хранится в куче вместе с самим объектом.
- **Ошибка переполнения:** `java.lang.OutOfMemoryError` (возникает при исчерпании доступной памяти кучи).

## 5. Передача параметров в методы
В Java все параметры передаются исключительно по значению (`pass-by-value`). Механизм передачи различается в зависимости от типа данных.

### Примитивные типы
В метод передаётся копия значения. Любые изменения параметра внутри метода не влияют на исходную переменную, так как работа ведётся с независимой ячейкой памяти.

### Ссылочные типы
В метод передаётся копия ссылки на объект. Поскольку обе ссылки указывают на один и тот же объект в куче, изменение его внутреннего состояния (например, через методы-сеттеры) внутри метода отразится на оригинале. Однако переназначение самой ссылки (`obj = new Object()`) изменит только локальную копию и не затронет исходную переменную.

### Неизменяемые типы (Immutable)
Классы `String`, `Integer`, `Byte` и другие обёртки не предоставляют методов для изменения состояния объекта. Любые операции с ними создают новые экземпляры, поэтому при передаче в методы они ведут себя аналогично примитивам.

## 6. Ссылка null и обработка NullPointerException

### 6.1. Определение и применение null
`null` — это специальная ссылка, указывающая на отсутствие объекта. Примитивные типы не могут иметь значение `null`. Нулевая ссылка используется в следующих случаях:
- инициализация массивов ссылочных типов (все элементы по умолчанию получают значение `null`);
- поля классов ссылочного типа без явной инициализации автоматически получают значение `null`;
- явная инициализация локальных переменных, когда значение неизвестно на момент объявления.

### 6.2. Исключение NullPointerException (NPE)
Попытка вызвать метод или обратиться к полю переменной, содержащей `null`, приводит к выбрасыванию исключения `java.lang.NullPointerException`.

Для предотвращения ошибки необходимо выполнять проверку ссылки перед использованием, особенно при итерации по массивам объектов:
```java
for (int i = 0; i < books.length; i++) {
    if (books[i] != null) {
        System.out.println(books[i].getName());
    }
}
```
