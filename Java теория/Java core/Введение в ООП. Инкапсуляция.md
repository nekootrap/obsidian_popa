## 1. Основы объектно-ориентированного программирования
Java является объектно-ориентированным языком программирования. Архитектура приложений в Java строится вокруг объектов. Объект представляет собой экземпляр класса и обладает свойствами (данными) и методами (функциями), обеспечивающими взаимодействие с ним. Реализация программ на Java невозможна без использования классов и объектов. В рамках ООП программа рассматривается как совокупность взаимодействующих объектов, шаблоны которых описываются классами.

## 2. Классы и объекты в Java
**Класс** — это шаблон, определяющий структуру (переменные) и поведение (методы) объектов. Для создания класса в среде разработки используется функция создания нового Java-класса в выбранном пакете.

**Объект** — это конкретный экземпляр класса, которому можно передавать команды и который реагирует на них, используя свои данные. Один объект может соответствовать нескольким классам одновременно, наследуя их признаки. Свойства объектов могут быть общими или уникальными.

Создание объекта выполняется с помощью оператора `new`:
```java
Car car1 = new Car();
```

## 3. Методы и конструкторы
**Метод** — блок кода, выполняющий определённую задачу и допускающий многократное использование. Метод реализует поведение объекта. Он может возвращать значение определённого типа или быть помечен модификатором `void`, если не возвращает результата. Каждый метод должен решать одну конкретную задачу.

**Конструктор** — специальный метод класса, вызываемый автоматически при создании объекта оператором `new`. Он отвечает за инициализацию атрибутов объекта.

- **Конструктор по умолчанию** создаётся компилятором автоматически, если в классе не объявлен ни один конструктор. Не принимает аргументов. При отсутствии явной инициализации поля ссылочных типов получают значение `null`, числовые — `0`.
- **Конструктор с параметрами** позволяет задавать начальные значения полей при создании объекта. Порядок аргументов при вызове должен совпадать с порядком параметров в объявлении.

Важно: при явном объявлении хотя бы одного конструктора компилятор не создаёт конструктор по умолчанию автоматически. При необходимости его следует объявлять явно. Код конструктора должен содержать только логику инициализации состояния объекта.

## 4. Ключевое слово `this`
Переменная `this` используется внутри конструкторов и методов для ссылки на текущий создаваемый или вызываемый объект. Она позволяет однозначно идентифицировать поля объекта при совпадении имён с параметрами конструктора или метода, а также обращаться к текущему экземпляру в других методах класса.

## 5. Основные принципы объектно-ориентированного программирования
В ООП выделяют три фундаментальных принципа:
1. **Инкапсуляция** — сокрытие данных и объединение их с методами обработки внутри класса.
2. **Наследование** — возможность описания нового класса на основе существующего с частичным или полным заимствованием его свойств и методов.
3. **Полиморфизм** — способность объектов с одинаковой спецификацией реализовывать различное поведение.

Java позволяет использовать объекты с одинаковыми интерфейсами без информации о типе и внутренней структуре, что обеспечивает гибкость архитектуры.

## 6. Инкапсуляция и механизмы доступа
Инкапсуляция обеспечивает безопасность кода, скрывая внутреннюю реализацию и защищая данные от некорректного изменения. Доступ к данным регулируется с помощью модификаторов видимости и специальных методов.

### Модификаторы доступа
- `public` — доступ из любой части программы.
- `default` (пакетный) — применяется по умолчанию, если модификатор не указан; доступ ограничен текущим пакетом.
- `protected` — доступ в пределах пакета и для классов-наследников.
- `private` — доступ только внутри объявляющего класса.

Модификатор указывается в начале объявления переменной, метода или класса.

### Геттеры и сеттеры
Для работы с полями, объявленными как `private`, используются методы доступа:
- **Геттер** (от англ. get) — метод для получения значения поля объекта.
- **Сеттер** (от англ. set) — метод для установки или изменения значения поля объекта.

Использование этих методов позволяет внедрять проверку данных, фильтрацию или дополнительную логику при чтении и записи полей, что невозможно при прямом доступе к полям. Данные методы генерируются автоматически в современных средах разработки.

## 7. Пакеты и импорт классов
**Пакет** — механизм логической группировки классов, аналогичный файловой папке. Пакеты предотвращают конфликты имён, организуют структуру проекта и участвуют в управлении доступом.

Объявление пакета выполняется оператором `package` в первой строке файла. В коммерческой разработке принято использовать обратную нотацию доменного имени компании, далее следует название проекта и функциональный модуль (например, `com.company.project.module`). Полное имя класса включает название пакета.

**Импорт классов**
Оператор `import` позволяет использовать классы из других пакетов без указания их полного имени. Он должен располагаться после объявления `package` и перед определениями классов. Классы пакета `java.lang` импортируются автоматически. При наличии классов с одинаковыми именами в разных импортируемых пакетах необходимо использовать полные имена для устранения неоднозначности. Оператор не является обязательным, но значительно сокращает объём кода.

## 8. Краткое резюме
- ООП строится на взаимодействии объектов, создаваемых на основе классов.
- Конструкторы обеспечивают инициализацию объектов; ключевое слово `this` ссылается на текущий экземпляр.
- Инкапсуляция скрывает реализацию и защищает данные через модификаторы доступа (`public`, `protected`, `default`, `private`) и методы get/set.
- Пакеты организуют код и управляют видимостью, оператор `import` упрощает обращение к внешним классам.
